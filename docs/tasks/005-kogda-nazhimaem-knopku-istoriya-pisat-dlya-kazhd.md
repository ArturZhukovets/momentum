# Показывать конкретный тип тренировки в строке истории

## Идея
«Когда нажимаем кнопку история, писать для каждого айтема тип тренировки»

Пользователю нужно видеть в списке `/history`, какая именно это была тренировка
(бег/плавание/эллипсоид/зал/домашняя), а не только общую иконку кардио/силовой.

## Вердикт
Относится к боту: да.
Уже реализовано: частично — `formatters/workout.py::history_row_label` уже строит короткую
подпись для каждой кнопки истории, но тип тренировки в ней сведён к одной из двух иконок
(`💪` для `gym`/`home_workout`, `🏃` для всего остального), конкретное название типа
(«Бег», «Плавание», «Эллипсоид», «Зал», «Домашняя тренировка») не выводится.
Реализуемо: да, без изменений схемы — нужные русские подписи уже есть в
`texts/workout.py` (`TYPE_LABELS` / `type_label()`).

## План
Правки только в `formatters/workout.py`, в функции `history_row_label` (вызывается из
`keyboards/history.py::history_page_kb` при построении кнопок списка `/history`):

- убрать самодельную логику `icon = "💪" if workout.workout_type in (...) else "🏃"` и вместо
  неё использовать `texts_workout.type_label(workout.workout_type)` — эта функция уже
  возвращает готовую пару «эмодзи + русское название» (`"🏃 Бег"`, `"🏊 Плавание"`,
  `"🌀 Эллипсоид"`, `"💪 Зал"`, `"🏠 Домашняя тренировка"`) из `TYPE_LABELS` в
  `texts/workout.py`;
- собрать первую часть подписи как `f"{texts_common.fmt_date(workout.performed_on)} —
  {texts_workout.type_label(workout.workout_type)}"` (дата остаётся первой — по ней
  сейчас ориентируются при пролистывании), дальше по-прежнему через `" · "` добавлять
  либо `body_parts_line` (для типов с группами мышц), либо обрезанное описание, как сейчас;
  порядок и логика этой второй части не меняются;
- итоговая строка по-прежнему проходит через `truncate()` из `formatters/_shared.py`, так
  что расширение подписи типом тренировки автоматически укладывается в лимит
  `ROW_LABEL_LIMIT` (60 символов) — при большом количестве частей отрежется конец, это
  штатное поведение, ничего дополнительно обрабатывать не нужно.

Карточка детали (`formatters/workout.py::workout_card`, открывается по кнопке из списка)
уже показывает полный `KIND_TITLES[workout.workout_type]` первой строкой — её трогать не
нужно, задача касается только списка.

Новых строк в `texts/` не требуется — все нужные подписи уже существуют в
`texts/workout.py::TYPE_LABELS`. Изменений в `db/`, миграциях и клавиатурах не требуется:
`workout.workout_type` уже приходит в дата-классе `db/models.py::Workout`, который
`db_workouts.list_workouts` (см. `handlers/history.py::_page_view`) и так возвращает для
каждой строки списка.
